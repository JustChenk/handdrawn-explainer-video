# Series Video Planner（大主题 → N 集系列视频）

## Overview

一段万字长文或一个大专题，一集讲不透，按章节机械切又会碎。本 skill 提供一套经过实战验证的拆分逻辑：判体量 → 按认知弧重组 → 定链接强度 → 落系列规划 → 逐集制作与验收，最终得到一套"单集可独立看懂、合起来是完整体系"的视频合集。单集生产本身不在本 skill 范围（走 handdrawn-explainer-video skill），本 skill 管的是"集以上"的所有决策与协作模式。

## 配套 skill（同属 vibe-video-skills 合集仓库）

本 skill 位于 [vibe-video-skills](https://github.com/JustChenk/vibe-video-skills) 的 `skills/series-video-planner/`，与另两个 skill 串成完整链路：

| 阶段 | Skill | 干什么 |
|---|---|---|
| ① 拆集 | **`series-video-planner`（本 skill）** | 体量判断 → 拆分逻辑 → 链接强度 → 系列规划.md |
| ② 制作 | `handdrawn-explainer-video` | 每集的调研/分镜/动画/自检/渲染/交付（本 skill Step 5 派 SubAgent 时用的就是它） |
| ③ 封面 | `douyin-cover-generator` | 成片封面，默认 3:4 竖版（1080×1440）+ 4:3 横版（1440×1080） |

安装见合集仓库根 README：clone 一次后把 `skills/<name>/` 链接进所用工具的 skill 加载目录即可。

## 何时用 / 何时不用

- **用**：素材或主题体量超过单集容量（>180s 讲不完 / >1 个核心心智模型）；用户明说"系列、合集、多集、分集"
- **不用**：一集讲得完的主题直接走单集流程，别为拆而拆

## 工作流（5 步）

### Step 1 · 体量判断与素材解析

1. 抓全文：WebFetch 优先；微信等反爬页面用 curl+浏览器 UA 抓 HTML，再用 Python 去标签抽正文（正则剥 `<p>/<br>` 与标签，unescape），存为 md
2. 估算体量：中文字数 × 0.06~0.08 s/字 ≈ 讲透所需秒数。>180s 即进入系列流程
3. 列原始章节清单：章/节标题 + 一句话主旨 + 体量占比（后面重组的原料）

### Step 2 · 拆分逻辑（本 skill 核心）

四条原则，按序执行：

1. **不按章节机械切**：章节体量常不均（有的章值 3 分钟、有的值 30 秒），机械切必碎
2. **按认知弧重组**：把章节映射到学习顺序而非作者写作顺序。技术类常用弧：世界观（为什么）→ 结构（是什么）→ 机制（怎么给/怎么收）→ 原理（怎么快）→ 实战（怎么查）；叙事/社科类可用：钩子 → 破题 → 展开 → 收尾
3. **每集一个可独立成立的心智模型**：检验法——"能否用一句话说清本集让观众学会了什么？"说不出就继续合并或拆分
4. **番外机制**：与主线不咬合但内容量够的章节（进阶/工具/历史八卦）做番外，不进主线、不影响完整性

集数粒度参考：

| 素材体量 | 拆分 |
|---|---|
| ≤180s 讲完 | 1 集（不走本 skill） |
| 5-8 个可独立心智模型 | 5-6 集主线 + 可选番外（最常见） |
| 高度连续不可分（连续推导等） | 2-3 集，接受单集偏长（≤240s），减少链接负担 |

### Step 3 · 链接强度决策

三档光谱，默认推荐中间档**模块化系列（Modular Series）**：

| 档 | 特征 | 适用 |
|---|---|---|
| 完全独立 | 各集零交叉，重复铺垫 | 各集主题差异极大、消费完全单点 |
| **模块化系列（推荐）** | 单集能独立看懂，合起来成套 | 绝大多数情况 |
| 强连载 | 必须按顺序看 | 强情节/连续课程 |

判断依据：单集转发场景（公众号/B站/群分享）要求"可独立看懂"；系列沉淀要求"有追更线索"——两档都要，取中间。

模块化系列的三件链接器（轻耦合，缺一会散）：

1. **共享世界（主链接）**：统一视觉 IP + 一张贯穿全系列的主图（如"内存大厦"：上层虚拟楼层/中层 MMU 翻译官/下层物理内存）。每集开头 2s 主图点亮本集所在层，结尾回主图。观众一眼知道自己在体系哪一层，且不依赖前集
2. **回指（弱链接）**：用到前集结论时一句话复述，不逼观众补课（例："上集说过进程拿的是假地址——那它落在哪块真内存上？"）
3. **预告与菜单（引导）**：片尾 5s 下一集预告；简介区放系列目录 + 推荐观看顺序

### Step 4 · 落盘系列规划（开工前第一份文档）

创建 `<项目根>/<系列名>/`，写 `系列规划.md`（复制 assets/ 模板改）。必含四块：

1. **集目清单**：# / 片名 / 素材来源（原文章节）/ 定位一句话
2. **全局约定**：目录结构、统一视觉与主图各层命名、回指示例、推荐观看顺序
3. **勘误台账**：调研发现的全部来源错误逐条记录（原话 + 实情 + 出处），全系列生效，各集调研材料与分镜红线引用它
4. **制作进度表**

目录约定（贯穿全程）：

```
<系列名>/
├── 系列规划.md            # 拆分逻辑+勘误+进度（唯一入口文档）
├── research/              # 共享溯源留痕：序号-标题.md（URL/抓取时间/摘要/原文摘录）
├── Ep01-主题/             # 每集一个文件夹，四件套自包含
│   ├── 调研材料.md
│   ├── 视频分镜脚本.md
│   ├── 动画工程（html/js/assets）
│   └── 成片.mp4
└── ...
```

### Step 5 · 逐集制作（双线模式：主线验收 + 子代理制作）

每集执行五步：

1. **主线调研**：WebSearch 交叉验证 2-4 轮，关键数字必须溯源；查不到写"示意/约"，绝不杜撰。产出 research/ 留痕 + 本集 `调研材料.md`（核心问题 / 人话版概念 / 数据点表带溯源 / 金句候选 / 叙事线 / 勘误引用）
2. **主线写（或审）分镜脚本**：每幕一行（时间码/章节/画面要点/字幕金句），8 幕以内、钩子前 15s、系列元素三件套（点亮层/回指/预告）、附**硬数字核对清单**与**制作红线**（把勘误台账转成"禁止出现 X"）
3. **派 SubAgent 制作**：每集一个 general-purpose 子代理，封闭在本集文件夹。prompt 必须自包含：视频 skill 的 SKILL.md 路径、参考工程路径、环境命令（node/python/渲染/合成/precheck 全路径）、调研材料与分镜位置、自检要求（测试帧分批渲染、读图不可用时用 Pillow 像素统计兜底）、汇报格式。**一次可并行 2 集**（全量渲染阶段抢 CPU，仅降速不致命）
4. **主线验收**（不照抄子代理报告，独立复跑）：
   - precheck 静态自检退出码 0
   - ffprobe 规格：≤180s / 1080p / 24fps / H.264 / 无音轨
   - 测试帧与成片抽帧非空白（读图不可用时 Pillow：非纸底像素 >2% 判非空白，暗像素 <0.5% 判空）
   - 分镜硬数字与调研材料逐项一致
   - 产物全部归位，系列根目录外无散落
5. **汇报用户**：成片 present_files + 每幕一句话 + 遗留项（中间产物可删提示）

### 收尾 · 合集交付

全系列完成后交付：系列规划.md（勘误+进度）+ 各集成片 + 观看顺序；提示 frames/ 每集 1-2GB 确认后可删。

## 硬性规则

1. 单集 ≤180s（番外可短）；钩子必须在第 1 幕前 15s
2. 关键数据三层溯源：成片 → 调研材料 → research/ 原始来源
3. 来源错误一律进勘误台账并在成片修正——**绝不让错误进视频**
4. 每集每个专业概念配类比，初中生能复述大意
5. 产物归位：系列根目录外无散落文件
