# 生产笔记（Production Notes）

## 1. 实测数据

| 项目 | 结果 | 备注 |
|---|---|---|
| 渲染速度 | **≈ 21 fps**（720 帧 / 30fps / 34 秒） | 纯矢量 + 文字动画几乎不吃性能 |
| 对比手绘线稿 | 明显更快 | 线稿描边 + 抖动是主要开销 |

**成本结论**：这类视频可以放心用 SubAgent 批量生产，不必像手绘那样省着排队。

## 2. 踩过的坑

### 2.1 rAF 抢帧（最高频，症状最隐蔽）

**症状**：`--test "4.5,12.5,20.5"` 抽三个时间点，得到三张几乎相同的画面。

**原因**：工程 HTML 同时当"浏览器预览页"和"渲染源"。实时的 `requestAnimationFrame`
循环会把宿主 `renderFrame(t)` 设好的状态覆盖掉——宿主要第 12.5 秒，rAF 却把画面拉回此刻。

**解法**（模板已内置）：

```js
window.renderFrame = t => { window.__hostDriven = true; frame(t); };
(function loop(){
  if (!window.__hostDriven) frame((performance.now()/1000) % DURATION);
  requestAnimationFrame(loop);
})();
```

宿主接管后 rAF 立刻让位。已排队的回调也会因首行 return 而不再覆盖。

> `precheck.js` 会强制校验 `__hostDriven` 与 `renderFrame` 同时存在。

### 2.2 幕透明度互相污染

若对三幕都用「当前幕的 p」去算透明度，非当前幕会拿到错的值（例如 `p=0.5` 时幕 1 也被算成全不透明，
于是三幕叠在一起）。

**解法**：每幕按**自己的局域时间**独立算透明度，幕外自动归零：

```js
const sceneOp = p => easeOut(p/.04) * (1 - clamp((p-.94)/.06));
S1.style.opacity = sceneOp((t - SEC[0]) / LEN);
S2.style.opacity = sceneOp((t - SEC[1]) / LEN);
S3.style.opacity = sceneOp((t - SEC[2]) / LEN);
```

### 2.3 流场粒子的确定性

逐帧渲染不能依赖"上一帧残留"，必须能被任意跳播重演。用固定步长推进：

```js
while (flow.simT + 1/30 <= target + 1e-6 && guard++ < 900) stepFlow();
```

跳播跨度 > 0.6s 时先 `resetFlow()`。**guard 必须有**，否则 time 一旦倒退会死循环。
注意：正常逐帧渲染（t 递增 1/30）时每帧只补 1 步，开销极小；只有抽帧跳播才需要重演。

**配套要求：`resetFlow()` 必须用固定种子**重建粒子与随机序列。若用 `Math.random()`，
每次重演的初始分布都不同 → 抽帧看到的画面和全量渲染对不上，而且同一时间点渲两次也不一样。
模板内置 `mulberry32(20261014)`，把种子连同随机序列一起存进 `flow.rnd` 供重生复用。

### 2.4 流场"卷成涡核"

第一版把基角偏移设成 1.42 rad（≈81°，近乎纯切向），配合 0.030 的长拖尾。
短时间看没问题，但幕长 8s 以上的话粒子会持续绕圈、层层叠加，
最终在画面中心堆出一个明显的螺旋涡核 —— 完全丢掉参考片那种"发丝飞散"的观感。

**修正**：基角偏移降到 **1.05 rad**（补足径向分量）、清屏 alpha 提到 **0.042**（缩短拖尾）、
重生区从 ±150px 扩到 ±310px（避免快速堆成一点）。

> 教训：流场参数要**按最长的一幕**来调，不能只测开场那两秒。

### 2.5 幕时长改了但渲染参数没改

新增一幕却忘了改 `--dur` → 尾部的幕根本没被渲染出来。
**`precheck.js` 接受第二参数做交叉校验**：

```bash
node precheck.js video.html 168     # 和 __meta.duration 对不上就报错
```

### 2.6 「空洞幕」返工（v1.0.0 成片的通病）

**症状**：成片中后段出现「纯黑底 + 孤立几行文字」的幕——单看每一幕都"符合极简"，
连起来看却越来越空，观众正是在这里流失（159s 实测成片的完播掉落点与这些幕重合）。

**根因**：v1.0.0 只规定了幕内元素的登场时序，没有规定**一幕必须有几层**，
于是大量产出没有背景纹理层的幕。v1.1.0 起已固化为硬规则 ⑧。

**解法**：执行三层结构纪律——每幕 ≥2 层（背景纹理层 + 前景信息层）。
三层分工、组件（点阵网格 / 微光条目卡）与压场渐晕见 `style-spec.md` §5；
「空洞幕」已列入反面清单（`style-spec.md` §9）；分幕阶段按幕式选好 L1 背景
（见 `scene-patterns.md` 各幕式的背景层说明）。抽帧目检时把"有没有纯黑底孤立文字幕"
当作必查项（SKILL.md 阶段 5）。

## 3. 与系列其他 skill 的边界

| 事项 | 处理 |
|---|---|
| 逐帧渲染 / 编码 | **复用** `handdrawn-explainer-video/scripts/`，不要复制一份（单一事实源） |
| 字体 | 本风格**只用系统字体**，不需要 `assets/fonts/`（这是相对手绘 skill 的一大简化） |
| 封面 | 用 `douyin-cover-generator`，但必须切到暗色 + 橙强调，别沿用纸面手绘那套模板 |
| 系列拆集 | >180s 或多个心智模型时先过 `series-video-planner` |
