# 抖音高点击封面生成

## 概述

输入一份视频稿件（或主题要点），产出两张符合抖音信息流特性的高点击率封面：**3:4 竖版（优先，1080×1440）+ 4:3 横版（1920×1440）**。渲染完全由代码完成——HTML + Canvas 2D 绘制 + playwright-core 截图，与视频制作管线（handdrawn-explainer-video 的 render.js）完全同栈、同依赖、同 Chromium 探测逻辑。中文标题由 Canvas 排版，输出确定性、可复现，零积分、零外部生成能力依赖。

**硬性约束：禁止调用 ImageGen / VideoGen 等外部生成能力**（不可迁移、消耗额度）。封面视觉只能来自：① 程序化背景（本 skill 内置 5 种风格）；② 用户自有素材（视频抽帧、产品图等）。

## 何时使用

- 用户要为视频/图文制作抖音封面、信息流缩略图
- 用户提供稿件并提到「封面」「缩略图」「点击率」
- 已有成片或分镜，需要补封面物料

## 输入规范

### 最小输入

用户直接提供视频稿件全文即可，无需额外格式化。无稿件时，围绕主题追问 3 个要素：核心内容、冲突/反差点、目标受众。

### 结构化输入（可选）

若用户已标注，优先取用：

- 主题：视频核心内容
- 核心冲突 / 反差：用户点击的核心动因
- 结果 / 收益：用户看完的收获
- 核心主体：人物 / 产品 / 场景
- 关键词：封面核心词汇

### 输入禁止

- 无明确主题的零散文案
- 虚构稿件中没有的数据、案例、人物
- 要求使用与内容无关的素材凑数
- 要求调用外部 AI 生成能力（ImageGen 等）

## 核心规则库

### 一、高点击封面 8 项强制标准（「吸引眼球」可执行定义）

1. **标题钩子化**：优先反差 / 结果 / 问题 / 数字 / 反常识 / 悬念型标题，禁止中性平铺直叙
2. **缩略图可读**：主标题 8-12 字，粗体强对比，带描边/投影/色块；竖版标题在上半区，横版标题在左侧/中心偏左
3. **单一视觉焦点**：单张封面只突出 1 个核心（人物表情 / 产品结果 / 冲突场景 / 超大标题），禁止信息堆砌
4. **强对比色彩**：深色背景 + 亮黄/白标题、红/橙色强调，禁止柔和低调风格
5. **情绪化人物**：人物用惊讶/严肃/指向镜头等强情绪，禁止证件照式微笑
6. **紧凑构图**：主体占比大、近景特写、背景简洁、视觉重心偏上，禁止远景、大面积留白
7. **克制配色**：主色 1 个 + 强调色 1 个 + 标题色 1 个，推荐黑黄白、黑红白、紫青白组合
8. **点击动机自检**：生成前必须回答——用户 3 秒能看懂吗？和同类有差异吗？不点会错过吗？

### 二、版式规范

> **默认比例：竖版 3:4（1080×1440）、横版 4:3（1920×1440）**，两张一套交付。
> 其他比例仍可用 `--ratio 9:16|16:9|1:1` 或 `--size WxH` 指定，但默认走 3:4 / 4:3。
>
> **竖版优先，且要把竖版当主交付**：竖版封面吃的是手机信息流，曝光量通常远高于横版，
> 缩略图又只有巴掌大——竖版的字号层级、对比、安全区任何一处不合格，直接反映到播放量上。
> 所以：竖版先渲染、先自检、先把问题改完，横版再做视觉复用（同一套文案与版式，只换坐标）。

**谁是主角：`--layout title`（默认）与 `--layout brand`**

封面第一眼必须先读到一句话，这句话叫主角。两条路选一条，不要两头都想要：

| 版式 | 主角 | 片名钩子的位置 | 什么时候用 |
| --- | --- | --- | --- |
| `title`（默认） | **片名钩子**（8-12 字，巨型亮色 + 描边 + 投影） | 就是主角 | 单条视频、系列认知已经建立、片名本身就是钩子 |
| `brand` | **系列标识**（`--kicker`，巨型亮色 + 描边 + 投影） | 降一档为白色副行，放在品牌行下方 | 系列化运营（观众先认系列、再认单集）；`--kicker` 通常是 6-10 字的系列名 |

`brand` 版式的硬规则（引擎已内建，不需要手工调字号）：

- 品牌行先占满标题栏拿到字号，片名再按品牌行的 **0.72 倍**降档 → 无论片名 6 字还是 12 字，主次都不会反转
- 品牌行穿主标题样式（`--title-color` + 描边 + 投影），片名降为 `--subtitle-color` 白色且去掉投影
- 竖版重心：品牌行 21.5% 高度、片名 40.5% 高度；横版重心：品牌行 36.5% 高度、片名 60.5% 高度
- 单行品牌名比同字数的单行标题更容易撑满标题栏：**系列名控制在 10 字以内**，超过就在 `--kicker` 里用 `\n` 手工断行
- 微调用 `--kicker-scale` / `--title-scale`（默认 1），不要靠改文案去凑字号

**横版封面（4:3，1920×1440）**

- 适用场景：横版视频、多平台横版展示、公众号/B站头图
- 版式结构：左侧大标题 + 右侧人物/产品主体或**大数字徽章** + 标题上方短标签 + 左上角系列标识
- 强化要点：加大标题字号、强化描边、提高主体占比，避免视频截图感
- 代码实现：标题左对齐于 5.5% 宽度处、垂直居中于 46% 高度（brand 版式：品牌行 36.5%、片名 60.5%）；标题栏可用宽度按画布"方正度"自适应（4:3 取 52%，16:9 取 46%，防止窄横版把字号压小）；标签在标题上方（22.5% 高度，须让开左上角标）；副标题在标题下方（78% 高度，brand 版式 80.5%）；图片背景自动加左侧渐变压暗（scrim）保证标题区对比

**竖版封面（3:4，1080×1440）**

- 适用场景：抖音信息流、移动端首屏缩略图（**主力交付物**）
- 版式结构：顶部系列标识 + 上半区大标题 + 中部短标签 + **中下部大数字徽章** + 底部副标题
- 安全规范：顶部标题不被遮挡、人物脸部避开平台 UI、主体不压底部操作区（右侧点赞/评论/分享图标列、底部用户名与配文区）
- 代码实现：标题居中于 30% 高度（brand 版式：品牌行 21.5%、片名 40.5%）；标签居中于 54.5% 高度；副标题居中于 88.5% 高度；程序化背景的装饰圆环尺寸同时受宽与高约束（`min(w,h)`），保证 3:4 / 4:3 下不溢出画布、不压字幕
- 自检必做：渲染后把成图缩到 **1/4（270×360）** 再看一眼——主角那行还认得出来才算过（见第 4 步）

### 三、标题类型匹配规则

| 稿件类型 | 推荐标题类型 | 示例 |
| --- | --- | --- |
| 知识方法 | 数字型 / 结果型 | 3 个步骤，快速理清思路 |
| 避坑经验 | 问题型 / 警示型 | 别再踩这 5 个坑 |
| 观点表达 | 反常识型 / 反差型 | 越努力，反而越差？ |
| 故事经历 | 悬念型 / 情绪型 | 那天，我差点放弃了 |
| 产品测评 | 结果型 / 对比型 | 真实用了 30 天，说说感受 |
| 教程教学 | 数字型 / 收益型 | 学会这一招，效率翻倍 |

### 四、视觉风格匹配规则（背景选型）

| 稿件类型 | 推荐背景风格（--style） |
| --- | --- |
| 知识干货、方法论 | `dazibao`（大字报：深色底 + 圆环角标 + 巨型黄标题） |
| 经验避坑、复盘 | `dazibao` 或 `rays`（警示光束） |
| 科技 / 软件 / 原理 | `grid`（科技网格）或 `glow`（辉光粒子） |
| 观点、情绪、故事 | `glow` + 强情绪标题；有人物素材时优先 `--bg` |
| 产品测评、开箱 | `--bg` 产品图 / 视频帧 |
| 商业、职场、认知 | `grid` + 深色商务配色（`--title-color` 白或青） |
| 生活、成长、心理 | `glow` 暖色粒子 + 情绪标题 |

## 执行流程

### 第 1 步：解析稿件

提取主题、冲突、结果、主体、关键词 5 大核心要素。标题按第三节表格匹配类型，主标题控制在 8-12 字；副标题 1 句（不超过 16 字），补充利益点或悬念；标签（tag）可选，4-6 字。

### 第 2 步：确定策略

确定标题类型、背景风格、配色组合（黑黄白默认；警示类黑红白；商务类白/青标题）。

### 第 3 步：渲染封面

用 `scripts/render-cover.js` 渲染，**竖版 3:4 优先，再出横版 4:3**：

```bash
# 竖版 3:4：大字报风（知识干货类默认，零依赖）
node scripts/render-cover.js --title "别再踩这5个坑" --subtitle "90%的新手都中招" --tag "避坑指南" \
  --ratio 3:4 --style dazibao --out 封面_竖版3x4_避坑.png

# 竖版 3:4：视频帧背景（已有成片时最推荐，画面与内容强相关）
node scripts/render-cover.js --title "程序住在假地址里" --subtitle "你看到的地址，可能是假的" --tag "Linux内存" \
  --ratio 3:4 --bg frame.png --darken 0.25 --out 封面_竖版3x4_内存.png

# 横版 4:3
node scripts/render-cover.js --title "..." --ratio 4:3 --bg frame.png --out 封面_横版4x3_主题.png

# 竖版 3:4：系列总览 / 知识合集（大数字徽章 + 系列标识 + 手工断行的两行巨标题，点击率最高）
node scripts/render-cover.js --title "687条建议\n只算四笔账" --subtitle "命 · 钱 · 自由 · 时间精力" \
  --tag "系列总览" --kicker "人生高性价比指南" --badge "34" --badge-caption "集全系列" \
  --ratio 3:4 --style dazibao --out 封面_竖版3x4_总览.png

# 竖版 3:4：系列名当主角（brand 版式）——系列化运营时每集都用这套，观众先认系列再认单集
#   品牌行自动拿大字，片名钩子自动降一档，配套横版只把 --ratio 换成 4:3 即可
node scripts/render-cover.js --title "687条建议\n只算四笔账" --subtitle "命 · 钱 · 自由 · 时间精力" \
  --tag "系列总览" --kicker "人生高性价比指南" --badge "34" --badge-caption "集全系列" \
  --layout brand --ratio 3:4 --style dazibao --out 封面_竖版3x4_总览.png
```

> `--title` 里的 `\n`：在 bash/zsh 用 `$'第一行\n第二行'`，PowerShell 用双引号里的 `` `n ``，
> 或者干脆用 `--config` JSON（JSON 字符串里写 `\n`）。直接写 `"第一行\n第二行"` 会被当成字面量
> `\` + `n` 印到画面上，渲染完记得读图确认断行。

背景素材获取（已有成片时）：`tools/ffmpeg.exe -ss 5 -i 成片.mp4 -frames:v 1 frame.png`，多抽几帧挑主体清晰、构图紧凑的。

> ⚠️ **视频帧背景的适用前提**：成片画面本身要「字少、主体明确」。若视频是手绘解说这类**画面上带章节标题/字幕/进度条**的类型，抽帧当背景即使压暗到 0.8 仍会与封面文案重影（封面标题撞视频里的贴纸标题），此时改用 `--style dazibao` 程序化深色底 + 大数字徽章，效果更干净、对比更强。

### 第 4 步：规则自检

对照 8 项强制标准逐项校验；任一不合格（标题超 12 字、无描边、多焦点、低对比）即调整重渲染。自检问题：

- 3 秒测试：**把封面缩到 1/4 大小（竖版 270×360）**，主角那行仍可读？（这一步必须真的把缩好的图看一眼，别只在脑子里推算）
- 主次测试：缩到 1/4 后，第一眼读到的是你想让人读到的那句吗？如果第一眼读到的是解释性文案、而主题被压成小字，就是主次颠倒——改用 `--layout brand`（主题即系列名）或把片名降级为副标题
- 差异测试：与同题材常见封面是否同质化？
- 错过测试：不点会错过什么，封面表达了吗？

### 第 5 步：输出交付

先竖版、后横版，先放图、后补说明；每张封面配 1 句设计逻辑说明（不超过 50 字）。文件命名：`封面_竖版3x4_<主题>.png`（1080×1440）、`封面_横版4x3_<主题>.png`（1920×1440）。

## render-cover.js 参数

| 参数 | 说明 |
| --- | --- |
| `--title` | 主标题（必填，建议 8-12 字；超 12 字自动折 2 行，优先按标点断行）。**标题里写 `\n` 可手工断行**——两行各 5-6 字能拿到比单行大得多的字号，缩略图可读性最好 |
| `--subtitle` | 副标题（竖版底部居中 / 横版标题下方） |
| `--tag` | 强调标签（4-6 字，圆角色块）。**默认字号 = 画布高度 6.6%**（2026-10-17 由 3.0% 上调，用户要求「红色部分要跟最大字体一样抢眼」）——已与主标题的实际渲染字号持平（主标题超 6 字会被 `fitTitle` 按宽度收缩，tag 4-6 字不缩，所以视觉重量相当、主次仍分明）。`--tag-scale` 可在此基准上再调 |
| `--kicker` | 系列/栏目标识（竖版顶部居中 / 横版左上角），用于建立系列认知，如「人生高性价比指南」。默认是小字；配 `--layout brand` 时它升为封面主角 |
| `--layout` | `title`（**默认**）= 片名是主角，kicker 只是小字标识；`brand` = **系列标识是主角**，kicker 拿大字（主色+描边+投影）、片名自动降一档为白色副行。`brand` 必须同时给 `--kicker` |
| `--kicker-scale` `--title-scale` `--tag-scale` | 字号倍率（`--tag-scale` **默认 2.2**，只接受正数，非法值回退 1）。给 `--layout brand` 微调用：`--kicker-scale 1.05` 再把品牌行放大一点，`--title-scale 0.9` 再把片名压一点。别用改文案的方式去凑字号。**⚠️ 注意 `--tag-scale` 是乘在 3.0% 基准上的**：默认 2.2 → 6.6%；若要回到旧的小标签规格传 `--tag-scale 1` |
| `--badge` `--badge-caption` | **大数字徽章**：一个数字/短词 + 可选小字说明，是全图视觉锤（如 `--badge 34 --badge-caption 集全系列`）。竖版在中下部居中、横版在右侧中部；短标题 + 大数字徽章是本 skill 点击率最高的组合 |
| `--badge-color` `--badge-text-color` `--badge-caption-color` | 徽章配色（默认红底白字 `#FF3B30` / `#FFFFFF`；`--badge-caption-color` 缺省随 `--badge-text-color`） |
| `--ratio` | 画布比例：`3:4`（**默认**，竖版 1080×1440）/ `4:3`（横版 1920×1440）/ `9:16`（1080×1920）/ `16:9`（1920×1080）/ `1:1`（1080×1080） |
| `--size` | 自定义画布 `WxH`（覆盖 `--ratio`，如 `720x1280`） |
| `--bg` | 背景图路径（自动居中裁切到目标比例；不传则用程序化背景） |
| `--darken` | 背景压暗系数（有 `--bg` 时建议 0.2-0.4，默认 0.25） |
| `--no-scrim` | 关闭横版左侧渐变压暗（有 `--bg` 时默认开启） |
| `--style` | 程序化背景风格：`grid`（默认，科技网格）/ `glow`（辉光粒子）/ `rays`（斜射光束）/ `dazibao`（大字报）/ `plain`（纯渐变） |
| `--title-color` `--stroke-color` `--subtitle-color` `--tag-color` `--tag-text-color` | 十六进制颜色，默认黄标题 `#FFD400` + 黑描边 `#141414` + 红标签 `#FF3B30` |
| `--bar-color` | 标题色块底色（设了就在色块上反色排字，黑黄警示风用） |
| `--font` | 自定义字体族名（默认系统字体栈：微软雅黑 → 苹方 → Noto Sans SC，weight 900） |
| `--no-shadow` | 关闭标题柔和投影 |
| `--config` | 从 JSON 文件读配置（CLI 参数优先），便于复杂封面复用 |
| `--out` | 输出 PNG 路径（必填） |

环境依赖：playwright-core（不下载浏览器）；Chromium 自动探测（CHROME_PATH → ms-playwright/puppeteer 缓存 → 系统 Chrome/Edge → agent-browser 缓存），与视频管线一致。

- `cover.js`：Canvas 2D 绘制引擎——画布比例表（3:4 / 4:3 / 9:16 / 16:9 / 1:1，默认 3:4）、程序化背景 5 种风格、图片背景裁切/压暗/scrim、标题自适应字号与折行、描边/投影/色块、标签/副标题/大数字徽章、两种版式（`title` 片名当主角 / `brand` 系列名当主角，后者按品牌行字号定档片名，保证主次不随字数反转）。确定性随机种子，同配置输出稳定可复现

### scripts/

- `render-cover.js`：渲染 CLI。参数解析 → 配置注入 → playwright-core 截图 → PNG（`--ratio` 默认 `3:4`）
